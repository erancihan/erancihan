# Review — chapter 07.B (The graphics pipeline)

**Persona:** graphics engineer who has lost an afternoon to a zeroed `colorWriteMask`.

**Verified:** 46.6% code, 24 blocks, largest 17 added lines, 100% anchored, lint
clean. Reconstructed tree builds; five pipelines created at runtime with
**validation silent** (confirmed by running it).

**What's right**
- The derivation is one I reproduced on real hardware-equivalent earlier in this
  project: two `OutputNotConsumed` performance warnings, one per unlit pipeline,
  because `unlit.vert` doesn't read the normal the pipeline declares. The reader
  hits it, counts the warnings against the pipelines, and fixes it with
  `MeshPositionOnly`. The closing point is the real one: **a silent run is the pass
  condition for every remaining checkpoint, and two warnings you have learned to
  ignore will hide the third.**
- Deliberate breakage picks the nastiest zero-default in Vulkan: delete
  `colorWriteMask` and *nothing* complains while all five pipelines silently write
  no colour. Explicitly pre-loads the black-screen bug for chapter 08.
- Fixed-function states that look like boilerplate each get a reason: dynamic
  viewport so a resize costs no pipeline rebuilds; `cullMode = NONE` traced back to
  chapter 08's self-correcting normals as a cost we chose; `lineWidth` required even
  on triangle pipelines; shader modules destroyed immediately after compilation.
- The per-instance-attributes alternative is explained and rejected with reasons
  (a `mat4` costs four attribute slots) rather than ignored.
- "Same shader pair, two pipelines" is used to introduce pipeline explosion and its
  two real answers.

**Findings**
1. No checker defects on this chapter.
2. 46.6% code is the second-highest in the guide. Justified: `makePipeline` is
   inherently a long struct-fill, and it is split into nine blocks averaging 9 added
   lines each, every one at a conceptual seam (input / raster / depth / blend /
   dynamic / assemble).

**Score: 9.5/10**
