# Review — unit C2 (canonical render layer: VulkanContext, Swapchain, Renderer, shaders, main, CMake)

**Reviewer persona:** skeptical senior Vulkan engineer who does not believe code
works until validation is silent and pixels are on screen.

**Verification actually run**
- `cmake -S . -B build && cmake --build build` — **configures, compiles and links**.
  All 8 shaders compiled to SPIR-V by the build's own custom command.
- `g++ -Wall -Wextra -fsyntax-only` on every TU: clean (VMA's own warnings are
  isolated in `VmaImplementation.cpp`, which exists for exactly that reason).
- **The game was executed** headless: Xvfb + Mesa lavapipe (`llvmpipe`, Vulkan 1.4)
  + `VK_LAYER_KHRONOS_validation`. It runs a real frame loop.
- **Screenshot captured and inspected.** Renders: deep-blue clear, tiling starfield,
  cyan ground grid converging to a horizon, the lit ship dart, red enemy octahedra,
  the centre reticle, and the hull bar — draining after a ram, which also proves
  collision → GameStats → HUD end to end.
- **Validation output: silent.** The only line on stderr is the device banner.
- **Resize path exercised:** four `xdotool` resizes (640x480, 1024x768, 300x200,
  1280x720) drove `Swapchain::recreate` four times. No crash, validation still silent.

**Findings**

1. **Real bug found and fixed by running it.** The grid originally emitted one
   full-length line per row (`z = -400 … +400`). Every Z-direction line therefore
   ran from far in front of the camera to far behind it, and **not one of them
   rendered** — the screenshot showed only the X-direction lines. Isolated by
   emitting Z-lines alone (nothing drew) and then shortening them to stay in front
   of the camera (a perfect converging grid appeared). Fixed by emitting one
   segment per cell, so no segment can span the near plane. This would never have
   been caught by inspection, and the original guide's grid code has the same shape.
2. **Two validation performance warnings found and fixed.** `unlit.vert` consumes
   only position, but the pipeline declared both mesh attributes.
   Added `VertexLayout::MeshPositionOnly` so the grid and bolt pipelines declare
   one attribute. Validation is now completely silent, which is what lets the
   chapters promise "a silent run means you got it right".
3. `VmaImplementation.cpp` is new (not in the original file map) — one TU owning
   `VMA_IMPLEMENTATION`. Add to chapter 01's file map.
4. `CMakeLists.txt` accepts `glslc` (LunarG SDK) or `glslangValidator` (what most
   Linux distributions package). The original guide assumed `Vulkan::glslc` only,
   which fails to configure on a plain Debian/Ubuntu box.
5. `renderFinished` is keyed per frame-in-flight, not per swapchain image. This is
   the known-imprecise form the original guide already flags; kept, still flagged,
   still pointed at chapter 14. Recent validation did not complain here.

**Concerns not fixed**
- All runtime evidence comes from a **software rasterizer**, not a real GPU. Frame
  pacing, `MAILBOX` behaviour and vendor-specific driver quirks are unverified.
  Correctness of API usage is well covered by validation; performance claims are not.

**Score: 9.5/10** — builds, runs, renders the intended image, and validation is
silent through startup, 8+ seconds of gameplay and four swapchain recreations. Two
real defects were found *because* it was run rather than reviewed.
