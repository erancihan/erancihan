# Review — chapter 09 (The game loop & timing)

**Persona:** pedagogy reviewer + gameplay engineer.

**Verified:** 45.6% code, 21 blocks, largest 18 added lines, 100% anchored, lint
clean. Reconstructed tree builds and runs; the window title reads exactly
`Space Fighter    score 0    hull 100%    deaths 0` as the checkpoint claims
(read back with `xdotool getwindowname`). Validation silent.

**What's right**
- The chapter's real subject is the *schedule*, and it earns it: the systems arrive
  two at a time, with each later chapter adding one line, so "the order is the rules"
  is something the reader lives rather than reads.
- `GameState.hpp`'s existence is justified by the include cycle it breaks, in the
  file's own comment.
- Small decisions get their reason: `update` returns by value so the output is
  visible in the signature; `MovementSystem` iterates the *smaller* store;
  `respawn` resets rather than recreates the player; the title updates 4×/s not 60;
  the minimise `continue` sits after the clock read so `lastTime` can't go stale.
- Deliberate breakage is two-part and both halves are observable: add a `Velocity`
  and watch `MovementSystem` and the grid snap do all the work with no new code;
  then raise `kMaxStep` to 10 and drag the window to see the teleport the clamp
  normally absorbs.
- The fixed-timestep section names the three cases that actually require it rather
  than presenting it as generically better.

**Findings**
1. *(fixed)* An unanchored `diff` block "fix it to use the local `eye`" was never
   applied by the replayer, so the emitted tree failed to compile with
   `'cam' was not declared`. **The build check caught this, not the lint.** The
   contrived two-step was replaced by writing the line correctly the first time — the
   derivation was weak anyway (a name that doesn't exist yet is a typo, not a lesson).
2. *(fixed)* One 22-line block split; one pseudocode block needed its illustration
   marker moved out of the code.

**Score: 9/10** — one block that silently did nothing, caught only because the
reconstructed tree is compiled rather than eyeballed.
