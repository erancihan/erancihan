# Review — chapter 08 (Meshes & geometry)

**Persona:** graphics engineer; also the person who found the grid bug.

**Verified — the strongest checkpoint yet.** The tree reconstructed from chapters
01–08 alone builds, runs, and **renders the promised image**: pale blue ship dart,
starfield, cyan ground grid receding to a horizon with lines running *both ways*.
Screenshot captured and inspected. Validation silent. `Mesh.hpp`, `Mesh.cpp` and
`Renderer.hpp` reconstruct **exactly**; `Renderer.cpp` differs only by the six-line
HUD pass that chapter 13 adds — confirmed by diffing.

48.4% code, 37 blocks, largest 18 added lines, 100% anchored, lint clean.

**What's right**
- **The derivation is a bug I found by running the canonical code, not one I
  invented.** The obvious grid — one full-length line per row — renders only the
  X-direction lines, because every Z-direction line spans from in front of the
  camera to behind it. The reader writes it, sees half a grid, and fixes it with
  per-cell segments. The generalisation ("a primitive that crosses the near plane
  is the edge case; the cheapest fix is to not have one") is the transferable part.
- The self-correcting normal is tied back to chapter 07.B's `cullMode = NONE` as a
  cost we accepted, not a free win.
- The starfield PRNG is seeded with a constant *and the reason is given*: debugging
  a renderer against a changing sky is its own kind of miserable.
- `firstInstance` is explained as the mechanism that lets one storage buffer serve
  every mesh with no per-group rebinding.
- Two passes over `groups` instead of one, with the reason (bucket by state).
- The symptom table pays off three earlier deliberate breakages by name —
  `colorWriteMask` (07.B), swapped attribute locations (07.A), depth cleared to 0.0
  (05.B) — each of which was planted precisely so it would arrive here.

**Findings**
1. **The verifier caught an ambiguous anchor**: `return m;` + `}` matched both
   `flat` and `starfield`. Added a distinguishing context line.
2. **The verifier caught a dropped file**: the word "throwaway" in a `main.cpp`
   location line made the tool classify it as scratch and exclude it, so the emitted
   tree had no entry point. Fixed the wording *and* tightened the detection to key
   on the `scratch/` path rather than a keyword — the tool was too eager, and a
   keyword appearing in ordinary prose should not change what a file *is*.
3. *(canonical simplified)* `recordFrame`'s `FrameData` parameter was unused —
   everything it needs is a member by then. Removed from the canonical source, which
   also removed a `(void)frame;` and two signature-change diffs from this chapter.

**Score: 9.5/10**
