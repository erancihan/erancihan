# Review — unit C1 (canonical core: math, ECS, components, meshes, systems, game, HUD, input)

**Reviewer persona:** skeptical senior C++/gameplay engineer who re-runs everything
and assumes the author got pointer lifetimes wrong.

**Verification actually run**
- `g++ -std=c++17 -fsyntax-only -Wall -Wextra` on all 3 TUs + all 13 headers standalone: clean.
- `work/tests/core_test.cpp` built and **executed**: 31 checks, all pass.
  Covers sparse-set swap-remove identity, gapless dense walk, `set` overwrite,
  deferred destroy across two stores incl. double-queue and double-flush,
  mesh vertex/index counts, outward-normal invariant on all three solids,
  projection near→0 / far→1 depth and the Y-flip sign, 720-frame game loop
  (ship/bolts/enemies present, enemy cap, HUD triangle count), bolt expiry,
  dt clamp under a 5 s hitch, and score climbing over a 6000-frame run.

**Findings**

1. *(fixed before writing)* `WeaponSystem::update` held a `Transform*` across
   `fireBolt`, which `push_back`s into the Transform store — a dangling pointer on
   reallocation. Now copies the transform first. Same hazard fixed in
   `EnemySystem::update` before `spawn`. **These two are the best derive-don't-present
   candidates in the guide** — the naive version compiles and usually appears to work.
2. `GameState.hpp` is new (not in the original file map). It exists to break the
   Game.hpp ↔ systems/*.hpp include cycle that `GameStats` would otherwise create.
   Must be added to chapter 01's file map.
3. Systems are header-only `inline` namespaces. Deliberate: it keeps
   `CMakeLists.txt` to 7 sources and spares the reader nine "add another .cpp"
   diffs. Worth one sentence of prose in ch09.
4. World constants (`kGridSpacing`, `kGroundY`, `kStarSpan`, `kStarCount`,
   `kGridHalfExtent`) live in `RenderTypes.hpp` because both the simulation
   (grid snapping) and the renderer (mesh generation, push constant) need them.
   Single source of truth; the original guide left these unstated in two places.
5. `Layer`/`overlaps` is exercised by the bolt→enemy path only; the ship→enemy
   path checks the pair directly, matching the original guide's stated design.
   Honest, and the guide says so.

**Concerns not fixed**
- Cannot execute anything GPU-dependent; this unit has none, so nothing is
  deferred here. All claims above are observed, not reasoned.

**Score: 9.5/10** — compiles warning-free under `-Wall -Wextra`, and every
behavioural claim the chapters will make about the simulation half is backed by a
test that ran.
