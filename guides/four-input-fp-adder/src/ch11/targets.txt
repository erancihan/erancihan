# exact files next to these. ch09's fp32_add2 is also the streaming oracle;
# ch10's fp32_add4_tree is the oracle for the pipelined tree.

# stream_cfg_p4.v ahead of tb_stream.v / tb_reset.v retargets the same
# harness source at the 4-stage pipeline (`define carries across files in
# command-line order) -- the manifest equivalent of -DDUT=fp32_add2_p4.
#
# Both streaming sweeps ship at FULL headline size (100k+ streamed
# transactions; ~10 s and ~37 s here) -- unlike ch10's 240k headline run,
# they fit the 60 s SIM_TIMEOUT with margin.

# teaches (a forgotten stage register, blocking in a bank, a combinational
# flag OR, a full datapath reset) compiles in total silence -- that is the
# point -- and each lives in the README's mutation record instead.
